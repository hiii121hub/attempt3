## B. Isolation milestone (partial, intentionally offline)

`a0cb3a9` adds `isolation/worker-spec.mjs`, its 21 tests, documentation and the test
command. The specification validates explicit quotas, broker UUID, digest-pinned
image, private user/PID/IPC/cgroup namespaces, non-root user, read-only image,
ephemeral bounded writable paths, dropped capabilities and no-new-privileges.
Image-declared persistent volumes and host-proxy inheritance are disabled. It
accepts no mounts, published ports, arbitrary environment or privileged arguments.
Cleanup plans target an inspected exact container ID with matching owner/session
labels; they cannot prune unrelated resources.

Networking is deliberately `none`: no web browsing is possible through this
prototype. It is not connected to the session manager, and executes no containers.
Neither its sample quotas nor its successful unit tests prove Chrome sandboxing or
resource enforcement. Details and Podman flag references: `isolation/OFFLINE-SPEC.md`.

Read-only Linux qualification: Linux/non-root/nested namespaces passed. Supported
Podman/rootless operation, delegated controllers, cgroup-v2 qualification and enough
subordinate IDs did not qualify. Unavailable Podman data is not evidence the kernel
actually runs cgroup v1. No container image or runtime integration was attempted;
the existing native stack remains unchanged in architecture and is unsuitable as
a hostile-user isolation boundary.

## C. Capacity and normal-cleanup repair

`5dc928c` fixes two actual lifecycle defects:

1. The old map-size check stopped counting sessions before resource teardown
   finished. Admission now uses a synchronous lease covering startup, active use
   and cleanup; failed-start rollback must finish before its lease is released.
2. `child.killed` indicated that a signal was sent, not process exit. Normal
   teardown now checks exit/signal status, sends TERM and escalates to KILL, then
   checks tracked children before deleting their profile and releasing capacity.

Retiring displays/VNC ports remain allocated during cleanup. Authorization is
removed immediately. Cleanup/accounting errors retain the reservation and log a
diagnostic rather than admitting beyond the cap. Shutdown awaits pending normal
cleanup. `/health` adds `occupiedSlots` to distinguish reservations from active
session count. This is a loopback diagnostic, not a new public route.

Production still defaults to one supervised tester. The existing validated
`POXEY_MAX_SESSIONS=5` option remains a release target, not an automatic new default.
A full broker returns the same HTTP 429 `MAX_SESSIONS` response. The existing
startup lock and bounded busy-only frontend retry remain; no ambiguous-network
retry or allowance change was introduced. See `CAPACITY-PREPARATION.md`.
